# Шпаргалка: как продолжать наполнение пакетов данных

Файл написан для того, чтобы работу можно было продолжить в новом окне
с нуля, без истории переписки. Всё, что нужно знать, — здесь.

## Что делаем

Пишем пакеты данных по машинам для прототипа «Автоподбор». Один пакет —
одно поколение одной модели. Цель, поставленная владельцем: закрыть
**весь каталог**, а не популярную выборку. Машины, снятые с производства
до 1980 года, из каталога убраны — на вторичке их нет.

Состояние на 20.09.2026: **211 поколений с данными из 7080**.

## Правила, которые не обсуждаются

1. **Ничего не выдумывать.** Каждая неисправность — из опубликованного
   источника. По этим данным покупатель отказывается от машины или сбивает
   цену; выдуманная болячка — это чужие деньги.
2. **Искать на любом языке, писать по-русски.** Английские, немецкие,
   японские, корейские, китайские форумы, отзывные кампании, техбюллетени —
   всё в дело. В приложении каждая строка по-русски.
3. **Источники расходятся — так и писать.** Прямо в тексте пакета: одни
   владельцы проходят триста тысяч, другие платят за ремонт на восьмидесяти.
4. **Списки — одним прогоном, от важного к неважному.** Никаких разделов
   «критичное» и «прочее»; серьёзность словом в каждой строке.
5. **Никаких демо-данных.** Прототип открывается пустым, как у нового
   пользователя: ни галочек, ни сохранённых ошибок, ни пробега.
6. **Не писать владельцу до конца работы.** Промежуточные отчёты не нужны.

## Порядок работы: одна партия

Партия — три машины. По каждой:

1. **Найти источники.** Поиск по названию поколения плюс «слабые места»,
   «болячки», «отзывы владельцев», «с пробегом»; на английском — `common
   problems`, `recalls`, `teardown`. Полезные: «За рулём», «Колёса.ру»,
   Дром, DRIVE2, vvm-auto, марочные клубы, NHTSA, KBA.
2. **Уточнить обозначение поколения в каталоге.** Каталог собран из
   линейки auto.ru и мешает платформенные коды с римскими цифрами:
   у Civic поколения `VIII`, у Soul `II`, у SX4 `Classic`. Пакет обязан
   называть поколение ровно так же, иначе машина продублируется.
   Смотреть так:

   ```bash
   node -e "const fs=require('fs');const S=eval(fs.readFileSync('catalog.js','utf8')+'; STUB_CATALOG');for(const [b,ms] of S){if(b!=='Honda')continue;for(const [m,body,g] of ms)console.log(m,'|',g.map(x=>x[0]).join(', '))}"
   ```

3. **Написать пакеты** во временный файл, например
   `%TEMP%\chunkNN.js`, в формате ниже.
4. **Дописать в конец `packs.js`** и проверить синтаксис:

   ```bash
   cat /tmp/chunkNN.js >> packs.js && node --check packs.js
   ```

5. **Прогнать проверку:**

   ```bash
   node tools/packs/validate.js
   ```

   Должно быть `problems: 0`. Исключение — два известных: `uaz-bukhanka`
   и `gazel-business`: в новом каталоге нет коммерческих машин, строки для
   них отсутствуют.

6. **Прогнать все машины по всем экранам в браузере.** Поднять сервер и
   выполнить в консоли страницы:

   ```js
   const bad=[];
   for(const id of Object.keys(CARS)){
     try{ SEL.carId=id; for(const s of SCREENS){ go(s); } }
     catch(e){ bad.push([id,e.message]); }
   }
   JSON.stringify({bad:bad.slice(0,5),packs:Object.keys(CARS).length})
   ```

   `bad` должен быть пустым. Браузер кеширует `packs.js`, поэтому перед
   прогоном: `await fetch('packs.js',{cache:'reload'}); location.reload();`

7. **Коммит и пуш.** Только `packs.js`, если каталог не трогали:

   ```bash
   git add packs.js && git commit && git push
   ```

```js
EXTRA_CARS["corolla-e170"] = {
  brand:"Toyota", model:"Corolla", gen:"E170", years:"2013–2018",
  body:"седан", updated:"20.09.2026",
  engines:[
    {key:"1ZR-FE", label:"1ZR-FE · 1.6 · 122 л.с.",
     gearboxes:["K313 · вариатор Multidrive S","механика, 5 ступеней"]}
  ],
  options:[
    {id:"cond", name:"Климат-контроль", spot:"блок с дисплеем"}
  ],
  paint:{min:90, max:120, repaint:200, filler:300,
    material:"Кузов стальной, подойдёт любой толщиномер.",
    quality:"Покрытие тонкое: сколы на капоте набегают быстро."},
  rust:[
    {id:"roof", place:"Крыша и её кромки", where:"на просвет сверху",
     prev:"частое", sev:"warn", cost:["warn","Средний"],
     why:"Тонкая краска, рыжие точки по сколам.",
     how:["Осмотреть крышу при хорошем свете.","Проверить кромки у рейлингов."]}
  ],
  issueSeq:["cvt","steer","glass"],
  issues:{
    "cvt":{title:"Вариатор Multidrive S", short:"Вариатор", gb:"K313",
      node:"Коробка", when:"от 100 000 км",
      sev:"bad", cost:["crit","Дорогой"], prio:1,
      chips:[["bad","Высокая"],["neutral","Коробка"],["neutral","вариатор"]],
      desc:"Развёрнутое описание: что изнашивается, с какого пробега, от чего зависит.",
      alert:["bad","<b>Короткая выделенная мысль.</b> И пояснение к ней."],
      steps:["Прогреть машину и проехать не меньше получаса.",
             "Разгоняться плавно и в пол, слушая гул."],
      costs:[["Замена жидкости","Средний","warn"],["Ремонт вариатора","Дорогой","crit"]],
      codes:[["p0011","P0011","Рассогласование фаз"]]}
  },
  dtc:RU_DTC,
  guides:[
    {title:"Проверить вариатор", cat:"Коробка",
     steps:[{t:"Что сделать.", h:"Почему это важно.", r:"Что считать нормой."}]}
  ]
};
```

Пояснения к полям:

- `sev` — `crit`, `bad`, `warn`, `ok`. Определяет и цвет, и место в списке.
- `cost` — пара «уровень, слово»: `["crit","Дорогой"]`.
- `prio` — 1, 2, 3: грубая группировка внутри сортировки.
- `eng`, `gb`, `opt` — привязка неисправности к конкретному мотору, коробке
  или опции. Значение обязано совпадать с `key` двигателя, началом строки
  коробки или `id` опции — это проверяет валидатор.
- `alert` — `null`, если выделять нечего. Внутри допустим только `<b>`.
- `codes` — ссылки на общий словарь `RU_DTC` в начале `packs.js`:
  `p0300`, `p0171`, `p0420`, `p0011`, `p0217`.
- `guides` — пошаговый осмотр: `t` действие, `h` зачем, `r` норма.

## Известные грабли

- **`python` в этой системе — заглушка из магазина**, молча ничего не делает.
  Только `py -3`.
- **Heredoc в bash ломается на больших кириллических текстах.** Писать
  пакеты файлом через редактор, а не через `cat <<EOF`.
- **Каталог переписывается параллельно.** Он собирается выгрузкой из
  auto.ru инструментами в `tools/catalog`. Руками его не править: правки
  затираются при следующей генерации. Подстраивать надо пакеты под каталог.
- **Коммерческих машин в каталоге нет.** «Буханка» и «Газель Бизнес» с
  готовыми пакетами висят без строки — валидатор их показывает, это
  ожидаемо.
- **Коммитить `git add packs.js`, а не `git add -A`**, чтобы не подхватить
  чужую незакоммиченную работу.
