# Сборка каталога

`catalog.js` в корне репозитория собран этими скриптами со справочника
auto.ru и руками не правится — правка переживёт ровно до следующей сборки.

## Порядок

```
node scrape.js          # марки -> модели -> поколения, кэш в brands/<марка>.json
node pass2.js           # добирает модели с числовым слагом (308, Mazda 6, Tank 300)
node transform.js       # brands/*.json -> ../../catalog.js
node reconcile.js       # проверка: каждый пакет сошёлся со строкой каталога
```

Скрипты работают из своей папки. `scrape.js` и `pass2.js` возобновляемые:
уже скачанная марка пропускается, так что прерванный запуск продолжается с
того же места. Полный проход — около 5000 страниц, по запросу в секунду,
примерно два часа в четыре потока (`SHARD_N=4 SHARD_I=0..3`), `DELAY`
задаёт паузу между запросами в миллисекундах.

## Что делает transform.js

Сводит рестайлинги в одно поколение с общим диапазоном лет, выкидывает
служебные страницы марки (`photo`, `engine`), определяет тип кузова по
самому частому слову на странице модели.

Отдельный шаг — коды поколений. auto.ru даёт заводской код не везде: у
Mercedes и BMW он есть, у Hyundai и Kia вместо кода римская цифра. Поэтому
`transform.js` читает `packs.js` и `index.html`, находит строку каталога по
годам и ставит ей код из пакета. Без этого приложение показало бы одну и ту
же машину дважды: раз с данными, раз как «Готовится».

## После добавления пакета

Новый пакет с кодом, которого нет в каталоге, даёт именно такую задвоенную
строку. Поэтому после добавления пакетов:

```
node transform.js && node reconcile.js
```

`reconcile.js` печатает пакеты, которые не сошлись с каталогом. Пустые
списки — всё сошлось. ГАЗ «Газель» и УАЗ «Буханка» в списке остаются
всегда: коммерческий транспорт auto.ru держит в отдельном справочнике, и
эти две машины живут в приложении только своими пакетами.
